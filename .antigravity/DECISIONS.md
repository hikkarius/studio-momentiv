## ADR-001: Відмова від важкого 9:16 відеорендерингу та Gradio UI (Історичне)
- **Статус:** Прийнято (до аудиту, зафіксовано з `PROJECT_MEMORY.md`)
- **Контекст:** Рендеринг вертикальних кліпів із детекцією облич (OpenCV YuNet), генерацією ASS-субтитрів та B-Roll займав багато часу й ресурсів, тоді як основна цінність для користувача — швидке виявлення вірусних моментів, таймкодів, хуків і миттєве скачування фрагментів.
- **Рішення:** Повністю видалено Gradio (`app.py`), `renderer.py`, `broll_service.py` та `engine/`. Проєкт переведено на архітектуру **AI Video Moments Analyzer** із FastAPI бекендом, SQLite та легким Vanilla JS SPA.
- **Наслідки:**
  - (+) Кардинальне прискорення UX та зменшення складності рантайму.
  - (-) Залишився значний обсяг мертвого коду (`constants.py`, `config_schema.py`, `utils.py`, `requirements.txt/opencv-python`) та застарілої документації (`README.md`, `.agents/rules/*`), який заплановано прибрати в рамках **DEBT-01 / DEBT-02**.

## ADR-002: Dual-Engine AI Аналіз (Gemini Multimodal Audio + Local Faster-Whisper)
- **Статус:** Прийнято (реалізовано, потребує стабілізації)
- **Контекст:** Повна локальна транскрипція довгих 1–3 годинних відео навантажує ПК, але окремим користувачам потрібна 100% локальна приватність або резервний варіант при недоступності Gemini File API.
- **Рішення:** Реалізовано два рушії аналізу:
  1. `gemini_cloud` (основний): екстракція MP3 64k, Chronological Audio Windowing (вікна по 150с із перекриттям 15с, до 4 паралельних потоків), завантаження у Gemini File API, дедуплікація перекриттів (overlap > 45%) за Virality Score.
  2. `whisper_local` (приватний / автоматичний fallback): локальний `faster-whisper` (CTranslate2) + SHA-256 кеш транскрипцій + текстовий чанкінг у `ai_selector.py` + евристичний fallback при відмові всіх моделей Gemini.
- **Наслідки:**
  - (+) Висока швидкість і відмовостійкість пайплайну.
  - (-) Потрібно виправити виявлені дефекти: визначення CUDA через `ctranslate2` замість `torch` (**BUG-03**), резолв `filter_mode` (**BUG-02**), аргументи fallback `validate_clips` (**BUG-01**), перевірку стану `ACTIVE/FAILED` у File API (**BUG-04**).

## ADR-003: Локальне сховище SQLite (WAL) + Файлова система з дедуплікацією
- **Статус:** Прийнято (реалізовано, потребує зміцнення інваріантів)
- **Контекст:** Локальній десктоп-студії потрібна нульова конфігурація бази даних, підтримка історії сесій, перевикористання завантажених відео без дублювання гігабайтних файлів і повне видалення ресурсів.
- **Рішення:** Використовується SQLite (`studio_data.db`) у режимі WAL з `PRAGMA foreign_keys = ON`, дедуплікацією за фінгерпринтом (розмір + SHA-256 перших і останніх 64 КБ) та перевіркою посилальної цілісності перед видаленням фізичного відео.
- **Наслідки:**
  - (+) Простий деплой, швидке відкриття повторних сесій, економія дискового простору.
  - (-) Потрібно замінити `INSERT OR REPLACE` на `UPSERT` (`ON CONFLICT DO UPDATE`), прибрати `init_db()` з рівня імпорту модуля (**DB-01**) та ізолювати директорії `web_uploads`/`web_output` через конфігурацію для чистого тестування (**TEST-01**).

## ADR-004: Запровадження системи постійної пам'яті `.antigravity/` та суворого Multi-Agent Pipeline
- **Статус:** Прийнято (2026-11-18)
- **Контекст:** Існуючий файл `PROJECT_MEMORY.md` та `.agents/rules/*` частково застаріли і не відстежують динамічний стан багів, беклогу та архітектурних рішень між сесіями. Автоматичний `review_agent.py` перевіряє лише базові патерни і пропустив низку критичних багів і вразливостей.
- **Рішення:** Запровадити структуровану пам'ять у `.antigravity/` (`ARCHITECTURE.md`, `STATE.md`, `DECISIONS.md`) як єдине актуальне джерело правди для команди `[PM] -> [Architect] -> [Dev] -> [Auditor] -> [Reviewer]`. Кожна наступна задача проходить повний життєвий цикл із фіксацією результатів у `STATE.md`.
- **Наслідки:**
  - (+) Нульова втрата контексту між сесіями, контрольований технічний борг, прозора пріоритезація.
  - (-) Необхідність синхронізувати або заархівувати застарілий `PROJECT_MEMORY.md` та `.agents/rules/*` (заплановано у **DEBT-02**).

## ADR-005: Посилення периметра безпеки локального API та нативне CUDA-зондування через CTranslate2
- **Статус:** Прийнято та реалізовано (Sprint 1, 2026-11-18)
- **Контекст:** Аудит виявив ризики Stored XSS через `/api/upload` + `/api/media`, prefix-bypass path traversal у `download_from_url()`, відсутність валідації `project_id`, відкритий CORS (`*`) на локальний API та хибне визначення `CUDA=False` (через перевірку відсутнього `torch`).
- **Рішення:**
  1. Запроваджено whitelist відео/медіа розширень, `MAX_UPLOAD_BYTES` та заголовки `X-Content-Type-Options: nosniff` + `Content-Security-Policy: sandbox` для `/api/media`.
  2. Усі файлові операції переведено на `Path.resolve().is_relative_to(...)`, додано `_validate_project_id()` та SSRF-фільтр для loopback/приватних хостів у `download_from_url()`.
  3. CORS обмежено до локальних origins (`127.0.0.1:8000`, `localhost:8000`) із можливістю перевизначення через `CORS_ALLOWED_ORIGINS`.
  4. `probe_gpu_capabilities()` переведено на первинну перевірку `ctranslate2.get_cuda_device_count()` (нативний рушій `faster-whisper`) із fallback на `torch`.
  5. Директорії `UPLOADS_DIR` і `OUTPUT_DIR` винесено в конфігуровані змінні модулів для повної ізоляції тестів у `tests/conftest.py`.
- **Наслідки:**
  - (+) Закрито 3 вразливості та 3 критичні функціональні баги; Faster-Whisper на RTX 4050 бачить `CUDA=True`; тести більше не засмічують `web_output/`.
  - (-) Якщо студія запускатиметься за зовнішнім reverse-proxy чи на іншому порту, потрібно задати `CORS_ALLOWED_ORIGINS`.

## ADR-006: Стабілізація конкурентності, SQLite UPSERT, кешований GPU-проб та безпечний DOM
- **Статус:** Прийнято та реалізовано (Sprint 2, 2026-11-18)
- **Контекст:** Повторні підпроцеси GPU-зондування на кожен запит, глобальний lock на нарізку кліпів, синхронний I/O в `async def stream_media`, `INSERT OR REPLACE` із каскадним стиранням дочірніх записів, імпортний сайд-ефект `init_db()`, inline `onclick`-інтерполяція на фронтенді та необмежене зростання лог-файлу.
- **Рішення:**
  1. Усі перевірки GPU проходять через кеш `app_state.get_gpu_capabilities()`; при runtime-збої CUDA Whisper CPU-модель кешується через `app_state.set_whisper_fallback()`.
  2. Нарізка кліпів використовує per-path mutex (`_get_slice_path_lock`); `stream_media` переведено в sync `def` для неблокуючого виконання в threadpool Starlette.
  3. SQLite DAL переведено на `ON CONFLICT(id) DO UPDATE`, явний `rollback`, `db.init_db()` перенесено у FastAPI `lifespan`, додано явний прапорець `SKIP_MISSING_SOURCE_FILES`.
  4. Фронтенд очищено від inline `onclick` на користь `addEventListener`; логування переведено на `RotatingFileHandler` (`5 MB × 3`).
- **Наслідки:**
  - (+) Відсутність зайвих процесів `nvidia-smi`/`ffmpeg`, паралельна нарізка різних кліпів, збереження дочірніх даних при UPSERT, відсутність DOM XSS-векторів, контрольований розмір логів.
  - (-) Скрипти, які звертаються до `backend.db` напряму поза FastAPI `lifespan`, мають явно викликати `db.init_db()`.

## ADR-008: Повне видалення хмарного аудіорушія Gemini та перехід на Faster-Whisper + Gemini Text
- **Статус:** Прийнято та реалізовано (Sprint 4, 2026-11-19)
- **Контекст:** Реальне тестування користувачем показало незадовільну якість хмарного мультимодального аналізу аудіо через Gemini File API: неточні таймкоди, галюцинації хуків, розсинхрон виділеного тексту із фактичним звуком у відео. Водночас локальний Faster-Whisper (CUDA) показав стабільно високу точність word-level таймкодів. Також користувач відзначив незручність життєвого циклу сесій (неможливість деактивувати обрану сесію та залипання старих моментів при виборі нового відео).
- **Рішення:**
  1. Повністю видалено `_analyze_via_gemini_multimodal_audio`, генерацію нарізок `audio_chunk_*` та перемикач рушіїв на фронтенді (`engine-selector`).
  2. Пайплайн стандартизовано виключно на: **Faster-Whisper (CUDA / CPU fallback) + Gemini Text Virality Reasoning**.
  3. Faster-Whisper покращено: введено `condition_on_previous_text=False` для блокування зациклення фраз, налаштовано VAD (`min_silence_duration_ms=400`, `speech_pad_ms=200`), додано конфігурований `beam_size: 5` у `config.yaml` / `config_schema.py` та розширено український промпт пунктуації.
  4. Повністю оновлено життєвий цикл сесій: додано `resetStudioState()` для миттєвого очищення вітрини моментів, зупинки відеоплеєра та очищення `video.src`, toggle-деактивацію сесії при повторному кліку в історії, кнопку «✕ Скинути вибір» в активному банері та очищення старих результатів при кліку «➕ Завантажити інше відео» або старті нового завантаження.
- **Наслідки:**
  - (+) 100% точність таймкодів і хуків (єдине джерело правди транскрипту); суттєво чистіший і простіший UI; відсутність "залипання" старих сесій чи витоків пам'яті відеоплеєра.
  - (+) Усі 150 тестів успішно пройдено, тестове покриття становить **88%**, `review_agent.py --e2e` видає вердикт "БЕЗДОГАННИЙ".

## ADR-009: Генерація динамічних .SRT субтитрів (CapCut/Shorts) та інтерактивне підрізання меж (Trim)
- **Статус:** Прийнято та реалізовано (Sprint 5, 2026-11-19)
- **Контекст:** Користувачеві необхідна можливість окремого експорту субтитрів для кожного виділеного кліпу (сумісних із CapCut, DaVinci, Premiere) та інтерактивне точне підрізання фрагментів перед скачуванням або монтажем.
- **Рішення:**
  1. Створено модуль `subtitles_generator.py`: генерація відносних субтитрів `00:00:00,000` на базі кешованих слів Whisper (`word_timestamps`) з динамічним розбиттям по 2–4 слова на рядок (Shorts/CapCut style), розбиттям за пунктуацією та надійним інтерполяційним фолбеком на сегменти.
  2. Додано REST API ендпоінти: `GET /api/projects/{id}/clips/{idx}/export-srt`, `GET /api/projects/{id}/export-all-subtitles` (ZIP архів усіх субтитрів) та `PUT /api/projects/{id}/clips/{idx}/trim` (з валідацією $0 \le start < end \le duration$, $duration \ge 5.0c$).
  3. У `backend/db.py` реалізовано `update_clip_bounds()`, що атомарно оновлює межі, тривалість та форматовані поля кліпу в базі SQLite, а також очищує кешовані нарізки та субтитри в `web_output/{id}` для негайного перезастосування.
  4. На фронтенді впроваджено інтерактивне модальне вікно `trimModal`: вбудований прев'ю-плеєр, відображення поточного часу, кнопки точного кроку (`±0.2с`, `±1с`), авто-зупинка на кінці моменту та миттєве оновлення картки кліпу в DOM.
- **Наслідки:**
  - (+) Повноцінний конвеєр підготовки контенту для CapCut/TikTok без необхідності сторонніх конвертерів; можливість мілісекундного підгону меж фрази без перезапуску ШІ-аналізу.
  - (+) Усі 160 тестів пройдено успішно, загальне покриття збережено на рівні **88%** (модуль субтитрів покритий на 93%), `review_agent.py --e2e` видає вердикт "БЕЗДОГАННИЙ".
